# Deploying Leaflet to leaflet.chat

Leaflet's web build is a static site: `pnpm build:web` produces `dist/`, and
any host that serves those files over HTTPS at the site root can run it.
Cloudflare Pages is the reference setup because the reading-rooms relay
(`workers/rooms`) is a Cloudflare Worker on the same account.

## Build

```text
pnpm install
pnpm build:web        # tsc, then the app (--mode web), then the service worker
pnpm analyze          # optional: writes dist/bundle-report.md with gzip/brotli sizes
```

`dist/` contains:

| Path                    | What                                                                  |
| ----------------------- | --------------------------------------------------------------------- |
| `index.html`            | the shell, with the Content-Security-Policy meta tag injected         |
| `assets/*.js`, `*.css`  | hashed, immutable chunks (`react`, `motion`, `yjs`, `qr`, …)           |
| `book-sw.js`            | the service worker: book protocol, offline app shell, share target    |
| `manifest.webmanifest`  | PWA manifest (install, shortcuts, share target, file handler)         |
| `icons/`                | app icons                                                             |
| `_headers`, `_redirects`| hosting rules, generated by `vite.config.ts` (see below)              |

The service worker precaches every file under `assets/`, the manifest and the
icons, keyed by a hash of the build. A deploy therefore reaches an open tab on
its next navigation (network-first for HTML) and the reader keeps working
offline for books already in the library.

## Cloudflare Pages

1. Create a Pages project from the repository (or `wrangler pages deploy dist`).
2. Build command: `pnpm build:web`. Build output directory: `dist`.
   Root directory: `leaflet-migration/leaflet` when building from the monorepo.
3. Custom domain: `leaflet.chat` (and `www.leaflet.chat` redirecting to it).
4. Nothing else to configure: `_headers` and `_redirects` are picked up from
   `dist/` automatically.

The same `dist/` deploys unchanged to Netlify (which reads the same two
files) or to any static host where you can set response headers by hand.

### `_headers`

Generated from the single CSP definition in `vite.config.ts` (`WEB_CSP`),
so the `<meta http-equiv>` tag in `index.html` and the response header never
drift apart:

- `/*` — the CSP (plus `frame-ancestors 'none'`, which only works as a
  header), `X-Content-Type-Options: nosniff`, a strict referrer policy, a
  `Permissions-Policy` that keeps the camera available to the app itself
  (QR pairing) and denies microphone/geolocation, and
  `Cross-Origin-Opener-Policy: same-origin`.
- `/assets/*` — `Cache-Control: public, max-age=31536000, immutable`.
- `/`, `/index.html`, `/book-sw.js`, `/manifest.webmanifest` —
  `Cache-Control: no-cache`, so a new deploy is seen on the next request.

`connect-src` allows any HTTPS origin, loopback HTTP (Ollama, LM Studio),
and `ws:`/`wss:` — readers bring their own AI providers and can point the
app at a self-hosted relay, so the policy cannot enumerate hosts.

### `_redirects`

`/*  /index.html  200` — the app is a single page; deep links such as
`/join#ABCD-EFGH-JKLM` must load the shell. Real files are matched first.

## The reading-rooms relay

Reading rooms (short codes, read-along presence, shared notes) use an
end-to-end-encrypted relay at `wss://rooms.leaflet.chat`, a Cloudflare
Worker with one Durable Object per room in `workers/rooms`. It is deployed
separately:

```text
cd workers/rooms
npm install
npx wrangler deploy
```

See `docs/ROOMS.md` for the protocol, what the relay can and cannot see, and
how to self-host it. The app's default relay URL is `wss://rooms.leaflet.chat`;
readers can change it in the sync settings.

## Checklist before going live

- HTTPS on the apex domain: service workers, the camera (QR pairing), the
  Web Share Target and the file handler all require a secure context.
- The worker is served from `/book-sw.js` with scope `/` (the default
  registration); `Service-Worker-Allowed` is only needed in dev.
- Open `/` once after deploying and confirm the worker installs (DevTools →
  Application → Service Workers) and that `leaflet-shell-<hash>` appears in
  Cache Storage.
- Android / Chrome: after installing the PWA, "Share → Leaflet" from a file
  manager delivers the EPUB to `/share-target`; the worker stores it in the
  `leaflet-inbox` database and redirects to `/?inbox=1`, where the app
  imports it. "Open with Leaflet" (the `file_handlers` entry) arrives through
  `launchQueue`.
- iOS / Safari: installs as a home-screen app and reads offline, but Safari
  implements neither `share_target` nor `file_handlers`; readers add books
  through the file picker or drag-and-drop (iPadOS). Camera access for QR
  pairing works in Safari 16+.
- `pnpm analyze` after a dependency bump: the first load should stay at the
  shell + `react` + `motion` chunks; `anthropic-sdk`, `yjs`, `qr`, `fflate`,
  `dompurify` and `turn` must remain lazy.
